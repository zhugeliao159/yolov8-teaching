显存需求的主要影响因素

因素变化规律
Model Size参数量决定权重的基础显存需求
Batch Size增大 Batch 通常增加输入与中间特征显存
Input Resolution提高分辨率通常增加中间特征和计算开销
Numerical PrecisionFP32、FP16、BF16 的存储开销不同
训练额外保存梯度、优化器状态及反向传播所需的中间结果，因此通常比推理占用更多显存。

GPU 显存容量评估 GPU Memory Usage and Capacity Planning

显存估算

模型权重显存Mweights = Parameters × Bytes per Parameter
总显存近似模型Mtotal ≈ Mfixed + Mdynamic(B, H, W) + Mworkspace

Mfixed：模型参数及训练状态等固定开销
Mdynamic：与 Batch、图像尺寸有关的动态开销
Mworkspace：临时计算空间

Batch Size 对中间特征的影响

Batch 16
Batch 32

固定分辨率和其他条件时，中间特征显存通常近似翻倍；固定开销及工作空间的变化会影响总量，因此总显存不一定翻倍。

示意图仅表示相对趋势，不代表实测显存数值。

GPU 容量评估流程

模型结构与参数量→训练配置→峰值显存测试→预留显存余量→GPU 选型

训练配置：Batch Size、输入分辨率、数值精度及优化器。

用 PyTorch 峰值显存统计和 nvidia-smi 观察实际运行开销，结合合理余量选择 GPU。

24—36 MIN · 代码

用已有模型开始训练

from ultralytics import YOLO
from dataset import PROJECT, dataset_config

model = YOLO(str(PROJECT / "weights" / "yolov8n.pt"))
results = model.train(
    data=str(dataset_config("charmander")),
    epochs=2,
    imgsz=640,
    batch=4,
    device=0,
    workers=0,
    verbose=False,
    plots=False,
)
print("模型保存位置：", model.trainer.best)

只看四个参数

epochs完整学习数据几轮
imgsz输入图片的尺寸
batch每批处理多少张图片
device使用哪张 GPU

这里从已预训练的 yolov8n.pt 出发，继续训练称为微调。

评估与改进

有分数，更要看真实效果

Loss · 训练损失

训练过程中衡量预测误差的指标。一般希望逐渐下降，但不保证每一轮都下降。

mAP@0.5 · 检测指标

综合衡量检测效果的指标，通常越高越好；要结合验证数据理解。

COCO128 训练和验证使用同一批图片，课堂分数不能证明模型对真实新场景的泛化能力。小火龙验证集仅 3 张，同样不足以可靠评估。

工程循环：发现问题 → 补充多样数据 → 检查标注 → 重新训练 → 用新数据复测
